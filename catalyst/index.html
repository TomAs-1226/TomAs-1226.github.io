Why

A mechanism is a description

Every FRC season a team rewrites the same elevator, arm and shooter: motor setup, feedforward, soft limits, simulation, logging. Catalyst turns that into a description of the mechanism. You say what it is; the library does the rest the same way every time. 

// Catalyst 2.0: a two-motor elevator with named positions
LinearMechanism elevator = new LinearMechanism(
    LinearMechanism.Config.builder()
        .name("Elevator").motor(13).follower(14, true)
        .motorType(MotorType.KRAKEN_X60)
        .gearRatio(10.0).drumRadius(0.0254)
        .range(0.0, 1.2).mass(5.0)
        .pid(50, 0, 0.5).gravityGain(0.35)
        .motionMagic(2.0, 4.0, 20.0)
        .position("STOW", 0.0).position("HIGH", 1.1)
        .build());

new Trigger(operator::getYButton).onTrue(elevator.goTo("HIGH"));

That elevator comes with Motion Magic, gravity feedforward, a physics simulation, SysId, live tuning and telemetry under /Catalyst/Elevator/, without another line.
